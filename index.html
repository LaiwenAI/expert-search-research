面向专家检索的高效证据搜索与持续优化

Efficient Evidence-Based Expert Search with Optional Continual Improvement

最近更新时间：2026-11-18 19:49（北京时间）

1. 研究背景（Background）

专家检索（Expert Search / Expert Finding）旨在根据用户的自然语言需求，从大规模候选人集合中发现、检索并排序最合适的领域专家，广泛应用于校企合作、技术转移、科研合作和人才匹配等场景。

与传统文档检索不同，专家检索不仅需要发现相关信息，更需要以已有教师画像为基础，综合论文、专利、科研项目等多源证据，判断专家与具体需求的匹配程度，并给出可核验的推荐理由。结合经典 Expert Finding 研究及近期 Agentic Search、反馈学习与成本优化工作，专家检索面临以下主要挑战：

  1. 需求差异与语义鸿沟（Demand Heterogeneity & Semantic Gap）：企业需求不仅任务类型不同，明确程度、约束数量、知识跨度和所需检索推理也存在差异。例如“找一位研究计算机视觉的教授”可以直接检索，而涉及复杂工艺条件或跨学科问题的需求可能需要澄清、拆解和多轮搜索；不能对所有查询套用同一种推理流程。
  2. 多源异构证据融合（Heterogeneous Evidence Fusion）：论文、专利和科研项目分别反映专家的不同能力，单项成果与需求相关并不意味着专家整体适合；需要根据具体需求融合多源证据，评估专家的技术适配程度与实际贡献。[1][16]
  3. 多维匹配与约束满足（Multi-criteria Expert Matching）：企业不仅关注专家的研究方向，还可能要求特定的技术能力、工程经验、成果成熟度及合作条件。不同需求类型对应不同的匹配标准，需要区分硬性约束与软性偏好，并动态调整专家排序。
  4. 能力时效与贡献归因（Expertise Dynamics & Contribution Attribution）：专家的研究重点与实际能力随时间变化，且参与同一成果的不同人员，其具体贡献可能存在差异。仅凭成果发表时间、数量或署名信息，难以准确判断专家当前的研究能力及其在相关技术方向上的实际贡献。[15]
  5. 复杂检索与停止决策（Agentic Retrieval Decisions）：不同需求需要不同的查询拆解、检索轮次、工具调用与证据读取深度；智能体必须判断何时继续探索、何时已有足够证据可以停止。[2]
  6. 反馈利用与持续学习（Feedback Learning）：用户的文字纠错、对专家的选择行为与后续合作结果分别构成显式、隐式和延迟反馈，且存在信号稀疏、偏好混杂及结果延迟等问题。需要从这些反馈中学习可迁移的检索策略，同时控制旧任务能力退化。[3]
  7. 质量、延迟与成本权衡（Quality–Efficiency Trade-off）：更复杂的推理和更多次检索可能提高匹配质量，却增加响应延迟与计算费用。不同任务应采用不同的模型和搜索预算，而优化时还需要考虑反馈生成及训练的总成本。[7]

2. 核心科研问题（Research Questions）

How Can Expert Search Agents Achieve Evidence-Grounded Matching and Continually Improve Retrieval Quality and Computational Efficiency?

如何构建能够理解复杂技术需求、进行可信专家匹配的智能体，并通过在线与离线经验持续优化其检索质量、决策策略和计算效率？

  1. RQ1：需求分层理解与语义匹配（Demand Understanding & Semantic Matching）：如何识别需求类型、技术方向、显性与隐含约束、信息完整性及跨领域知识跨度，将简单主题查询与复杂场景需求转化为准确、可执行的检索表示？如何避免不必要的复杂推理，同时保证复杂需求得到充分理解？[1]
  2. RQ2：多源证据融合与专家能力评估（Evidence-grounded Expertise Assessment）：如何利用已有教师画像中的论文、专利和项目，结合需求类型、能力时效与个人成果贡献差异，识别专家的技术优势并满足硬性约束，形成有来源支持的专家级排序？[1][15][16]
  3. RQ3：质量约束下的自适应检索决策（Quality-constrained Retrieval Decisions）：如何根据技术需求的复杂程度与当前检索结果，动态调整检索策略、工具调用和模型选择，并判断何时停止搜索，以在保证专家匹配质量的前提下降低响应延迟和计算成本？[2][7]
  4. RQ4：反馈驱动的持续学习（Feedback-driven Continual Learning）：如何从自然语言纠错、最终选择的专家、交互轨迹和后续对接结果中提取学习信号，区分需求理解、证据判断、排序和搜索决策中的错误，并结合离线经验更新策略、控制遗忘？[3][4]
  5. RQ5：检索质量与计算效率的联合进化（Joint Quality–Efficiency Evolution）：如何联合优化专家匹配质量、证据支持度和总计算成本，通过经验积累、策略训练、评估及版本发布，使不同需求类型上的收益持续存在，而非仅改进单次查询？[8]

3. 研究目标（Research Objectives）

主线与研究假设：构建无需用户历史反馈即可运行的高效、低成本且有证据支持的专家搜索框架，结合公开与企业数据检验其相对强基线的质量—成本表现。探索开源决策模型、向量模型训练、层次索引和可选教师蒸馏；在线／离线反馈驱动的持续优化作为次要贡献，单独验证。现有实验尚未证明整体质量和效率同时提升。

围绕上述五个科研问题，本研究以可独立运行的专家检索 Agent 为基础，拟实现以下目标：

  1. 需求分层理解与准确召回（对应 RQ1）：构建任务类型、技术方向、约束、明确度和知识跨度的结构化表示，使简单查询可直接匹配，复杂场景能准确拆解并召回相关专家。
  2. 专家能力评估与多源匹配（对应 RQ2）：利用已有教师画像综合论文、专利、项目、近期研究与个人成果贡献信号，区分方向相关性和实际技术适配性，提升专家级排序及约束满足程度。
  3. 质量可控的高效搜索（对应 RQ3）：依据需求表示与当前证据状态动态选择检索路径、模型、工具和停止动作，避免简单需求过度推理，在质量约束下降低延迟及成本。
  4. 基于反馈的长期能力提升（对应 RQ4）：利用在线反馈和离线经验改善未见过的查询，在持续更新中控制旧任务遗忘，提升跨领域泛化。
  5. 端到端的质量—成本协同优化（对应 RQ5）：将推理、反馈、训练和评估成本统一核算，降低单位成功检索的总成本，并通过长期实验验证净收益。

阶段依赖：P0 评测 → P1 开源强基线 → P2 轻量决策、索引与表示 → P3 初始框架端到端比较；P4 单独验证反馈驱动的后续迭代。

4. 研究内容与技术路线（Methodology）

主贡献候选。从首个查询起，智能体就按「这次取证能否改变 Top-K」分配检索预算。每一轮追踪专家满足了哪些硬约束、哪些证据仍缺失或冲突，再选择补召回、定向取证、冲突复核或停止。在线／离线学习作为次要贡献，在初始策略冻结后单独验证。

4.2 按约束的证据缺口分配搜索预算

核心假设。当两位专家的相关性相近时，下一步应由可能改变推荐的未决约束决定。例如，企业要求某工艺适用于低温并具备中试记录。已有论文支持低温实验时，应优先在项目或专利中查找规模记录。如果所有候选都缺少该工艺的证据，则应按该约束补召回专家。两种情况的查询长度和候选得分可以相同，最佳动作不同。

  1. 记录专家与约束之间的证据状态。从需求原文定位硬约束和软偏好。每个「专家 × 约束」单元记录未查、已查但证据不足、有支持或存在冲突，并关联来源、原文位置和日期。共享来源只需读取一次，个人贡献逐人核验。索引节点定位原文，最终支持度由原文判定。
  2. 按预期收益选择动作。从共享候选池出发，针对各未决约束构造补召回、读取原文、复核冲突、停止等有限动作。为动作估计两项量：核验结果会改变关键约束判定或 Top-K 的概率，以及动作带来的端到端增量成本。候选路径的排序分数接近时，优先检查有较大机会改变入选名单的约束；同一来源若能核查多个未决项，则合并读取。先用可复现规则运行，再用本地开源 Decision Model 估计动作收益。训练候选来自同一状态下多个动作的配对回放，记录各自的核验结果、名单变化与成本。真实评估用独立标注区分有益变化和错误换人。
  3. 验证停止与回退。提前停止需满足关键约束有证据，且独立验证集校准的漏失风险低于预设阈值。风险偏高时按预算回退完整检索或强化核验。把临时排序与结束取证分别决策。单次正判可提高候选优先级，但仅凭这一信号仍应保留复核机会。验证时比较固定轮询、正判即停、临时排序后继续和选择性第二来源复核。将确认失败、误晋升、证据不足以及核验支出分别报告。对复核规则同时记录两份来源都误判的频率和来源重合情况，按主张及来源分组估计不确定性。SciFact 实测 预算耗尽时返回已支持的推荐及未决约束。TREC 复核回放

同模型、工具、初始候选池与预算下，对比固定读取、候选分数优先、分差早停，以及用通用推理／行动循环的 ReAct 对照。补做去掉「专家 × 约束」状态和去掉 Top-K 影响估计的消融，区分收益来自多轮工具调用、证据状态还是预算策略。若固定预算下证据与排序质量无增益，等质量下也无端到端成本收益，则主张不成立。ReAct 原论文

4.3 企业技术需求分类与结构化理解（Demand Taxonomy）

需求分类属于 Agent 的查询理解阶段，与上游按教师采集论文、专利、项目并建立画像是两项不同工作。建议采用“任务意图分类 + 需求特征评估 + 多维属性标注”体系，允许一条需求具有多个任务标签；需求类型不等于检索难度，描述较长也不必然需要更多推理。信息检索文献指出，任务目标及搜索过程的差异对应不同的检索策略；技术转移实践也强调技术成熟度和实施条件。[17][18]

并行标注维度：除技术领域、应用场景、成果成熟度、性能指标和硬性约束外，单独评估需求明确度、澄清必要性、约束耦合、知识跨度及预计检索深度。这些维度用于决策，不是简单将需求二分为“简单／复杂”。

4.4 多源证据融合与专家匹配（Evidence-grounded Expert Matching）

分组索引的剪枝开销。在 73 条已探索的 CoF SIGIR 查询、189 位审稿人和 1,740 篇去重论文上，用冻结向量比较平面全量评分与每位专家最多 1、2、4 组的质心距离上界。三种布局在 Top-5、10、20 均复现全量最大来源分数的排序。以 Top-5 为例，分别评分约 100.0%、95.7%、76.6% 的原始来源，计入质心后，点积总量却达到平面的 110.9%、117.4%、119.9%。实验使用缓存向量，统计的是计算量，尚未测量延迟、企业匹配或来源支持。因此保留平面精确评分作为全库召回的强基线。复现实验

固定候选后的来源导航。同一批 73 条公开查询各固定 5 位稠密检索候选，每位取最多 3 篇来源。平面扫描平均评分 77.8 篇，用时 0.076 毫秒。四组上界剪枝平均评分 71.8 篇及 20.0 个质心，365 位候选的来源顺序全部一致，平均用时 0.133 毫秒。只读质心分数最高的一组平均用时 0.059 毫秒，保留了平面扫描 65.9% 的参考来源。这些数字来自缓存向量的单进程 CPU 评分，每条查询重复五次，未计入建树、查询编码、候选生成、原文读取和模型调用。参考来源按向量相似度定义，语义证据是否充分仍待人工验证。当前以平面扫描作为候选内证据选择基线。后续将检验原文读取昂贵或专家来源更多时，带回退的分组导航能否在完整成本上获益。复现实验

4.5 在线与离线经验学习（Online–Offline Experience Learning）

反馈机制的关键对照：现有模拟只记住需求与专家身份，并未解析纠错文本，因此不能据此判断自然语言反馈是否被理解。后续应冻结基础 Agent 和候选池，比较固定检索、专家身份记忆、真正解析纠错内容的记忆、自适应计算及其组合，并用身份交换和文本交换诊断各自作用。已有结构化反馈应用原型：预先填写的需求短语和专家所属来源引用均匹配，且调用方明确判定反馈适用时才调整候选顺序；缺少判断或存在冲突则弃权；这只是字面与归属检查，尚不解析自然语言或验证语义支持。六个手工边界例中，在人为对所有案例强制给出适用判断时，修复英文单词内部误匹配后仍有三个否定或排除场景被错误触发；这不是有代表性的准确率评测，也说明该规则不能作为语义安全检查。真实反馈、独立来源标注、按企业和近重复需求隔离的封闭测试仍需建立；研究方案尚未预注册。

反馈记忆敏感性：在已探索的 73 条公开查询上重复 30 次随机且相互重叠的划分，模拟纠错记忆相对固定稠密检索在新查询集上的软标签 P@5 平均差值为 +0.011；21 次划分为正、8 次为负、1 次为零。划分并非独立重复，阈值来自先前探索，反馈由审稿人标签模拟，不能证明真实持续学习或时间上的遗忘控制。后续应预先固定策略，在分组隔离数据与真实反馈上分别测量新任务、历史任务及完整成本。

已有证据归属、专家索引、双语查询和静态检索实验可作为持续进化的基础系统；后续需固定模型、索引与候选预算，单独识别反馈策略带来的变化。真实用户反馈尚未建立时，模拟反馈仅用于验证实验流程，并须与独立人工评价分开报告。

反馈信号：（1）显式反馈：自然语言纠错、评价；（2）隐式反馈：候选曝光、点击、收藏、最终选择或联系的专家；（3）结果反馈：沟通与合作进展。选择行为可作为偏好信号，但不等于专家能力的真实标注；训练时需记录曝光列表和排序位置，控制位置偏差与选择偏差，不能直接把未选专家当作负例。

  1. 在线经验：使用过程中收集的需求、自然语言反馈、结果曝光与点击、收藏、最终选择或联系的专家、搜索轨迹及后续对接结果；实时采集不等于每次交互后立即更新模型参数。
  2. 离线经验：历史搜索日志、人工标注、合成任务和成功／失败案例；需要质量过滤、来源追踪与训练／测试隔离。

重点研究如何将不同来源的经验转化为训练与决策优化信号，比较文字反馈学习、SFT／DPO、强化学习、经验回放与蒸馏。反馈采集、批量训练与线上发布分别设计，并针对需求理解偏差、候选召回错误、证据选择不当、排序偏差和决策失误建立反馈归因，避免把“在线反馈”混同于“实时在线训练”。

基于已有实验的选择：保留全量精确检索作为召回参照；小范围筛选在既有测试中可能因额外串行步骤抵消收益，不能假定候选越少整体越快。先比较固定路径与按证据状态扩展的路径，分别测量每阶段延迟和遗漏证据，再决定是否采用门控或停止策略。并发评估可继续扩大样本验证，但要同时记录排序稳定性、失败与限流。

  1. 检索路径选择：结合需求表示与候选质量，选择直接检索、定向澄清或分步搜索；简单主题查询不启动不必要的多轮推理。
  2. 动态检索：结合候选专家覆盖程度、画像证据可信度及当前证据充分性决定是否扩展搜索。
  3. 模型路由：根据任务难度与预期收益选择不同规模的模型。
  4. 自适应停止：继续搜索的预期收益不足以抵消成本时停止。
  5. 策略蒸馏：在离线优化阶段，将高质量但昂贵的多轮搜索轨迹压缩为更经济的策略，并检验质量损失。

6. 预期创新点（Expected Contributions）

论文主贡献：提出并验证初始即可高效运行、低成本且有可核验来源的专家搜索框架。可训练 Decision Model、Embedding、专家证据树与按需推理是候选设计，需依靠强对照、消融及完整成本证明各自作用；组合本身不自动构成创新。次要贡献：利用在线／离线反馈迭代改进，并独立验证净收益；不以真实反馈可用为初始框架的前置条件。

创新点一：面向专家与证据的高效初始搜索框架

主创新假设是按约束记录证据并估计每个动作的边际收益，从而决定扩展专家池、读取原文还是停止。证据树提供定位，开源 Decision Model 可学习动作收益。移除约束状态后保留相同模型和预算，检查收益是否来自更长的搜索或更强的模型。只有统一组件和预算的对照仍显示净收益，才将该机制作为主贡献。

创新点二：真实需求驱动的数据构造与评测

由 1,000 条真实父需求生成 5,000 对五类双语查询，保持分组、来源、生成／筛查状态及失败谱系；通过独立语义与专家证据标注建立可检验 benchmark。现有同模型筛查不等于金标，受限原文及衍生文本的公开须依据授权。

创新点三：专家级质量、证据与成本评价

分别评价专家匹配、需求约束、来源支持、个人贡献可判定性、双语一致性及端到端延迟／成本；用固定视图和未知标签界限处理缺失，验证指标与独立人工评价的一致性。综合指标和权重须通过验证，不能把已有统计工具直接称为新理论。

次要贡献：在线／离线可迭代优化

在冻结初始系统上，比较固定框架、反馈记忆、反馈驱动模型更新及其与计算策略的组合；明确区分模型、记忆、索引及数据变化，测量新任务、旧任务和迭代成本。模拟反馈仅用于开发，真实迁移收益需独立验证。

7. 实验设计与评价（Experiments and Evaluation）

近期执行原则：先冻结企业需求分组、索引快照和多系统候选池；在开发集定义判断规则及停止策略，在独立验证集定阈值，再在封闭测试集评估。基线至少包括 BM25、稠密精确检索、混合检索与有／无重排的固定流程；控制相同候选、语料及预算，分别报告索引构建、冷启动、查询编码、检索、证据读取、模型推理与端到端延迟、P50／P95、吞吐和资源成本。未完成的主实验及消融保持待测，不使用示意数据填充结果。

指标研究：以人工专家级相关性及硬约束成功率为主，分别报告证据支持、引用可核验性、时效、个人贡献是否可判断、跨语言表现与质量—成本曲线；缺失标注和未知贡献保持未知。新的综合指标先定义适用范围、权重和缺失值规则，并检验与独立人工判断的一致性，避免用合成标签证明自身有效。

7.1.1 P0 Benchmark 标注与发布协议

筛查覆盖率随意图变化：1,000 条约束型合成查询中 279 条未判定，不能只保留通过筛查的样本并当作完整基准。按需求意图和筛查状态抽样，双人独立审查，再按企业／父需求分组处理依赖；验证集确定策略，封闭集只用于最终比较。

人工标注：受训且有相关技术背景的标注者对需求类型、约束、专家级匹配与证据独立双人标注，争议仲裁；报告 Cohen’s κ 或 Krippendorff’s α、标签覆盖率及分歧。候选池使用多系统 pooling 并补充随机候选，评估池化偏差。LLM 裁判须用独立人工金标校准，不可由同一方法生成自我评价真值。

成功检索定义：主口径为 Top-K 中检出至少一位经人工金标认定满足硬性约束且证据充分的专家。用户选择、联系与合作达成是不同的业务指标，另行报告。单位成功检索总成本为总查询／检索工具／反馈／训练／评估摊销成本除以主口径成功查询数。

时间与合规：按需求和科研成果时间严格切分训练、验证、测试，固定索引快照并独立评估知识库更新。企业需求及教师数据先审查授权和脱敏范围；公开数据与受控评测分离。个人贡献缺少人工真值时只做分析性子实验。

观察不同更新轮次下的检索质量、证据可靠性与成本，同时在固定的旧任务测试集上检查遗忘。实验完成后分别展示质量、延迟与成本的阶段性变化。

7.5 消融实验（Ablation Study）

初始框架优先的消融：① 平面／分层索引和有无精确回退；② 冻结／微调／蒸馏 Embedding；③ 无模型规则／冻结／SFT／RL 决策器；④ 无蒸馏／开源教师／可选商业教师；⑤ 固定／自适应证据预算；⑥ 逐项拆除混合召回、来源核验和早停。控制训练数据、参数量、候选池和预算，报告单项及交互作用，训练和离线成本单列。

关键机制消融：在固定候选与数据条件下，比较有／无反馈、身份记忆／内容记忆、适用性判断、来源核验、单独预算策略与联合策略；对内容和专家身份分别交换，仅作为破坏关联的诊断。对层次索引比较平面索引及精确回退，计入构建与更新。正负及未完成结果均保留，不能只呈现某次最优运行。

7.6 需求与证据能力的专项评估（RQ1–RQ2）

结合已有发现，双语评测同时报告语义等价、专家排序与证据支持；来源角色索引须检查逐查询退化，不能只报告平均覆盖增益。涉及来源时间、引用量及个人贡献时，将可观察元数据和待验证的个人贡献信号分开，信息不足保持未知。

除总体排序指标外，分别评价需求理解、证据融合、能力时效、个人贡献信号、多维约束满足及推荐理由的来源支持。

该项实验尚未完成；结果将以实际数据及明确口径更新。

专项实验报告需求类型 Macro-F1、约束抽取准确率，并在直接检索、澄清和分步检索任务上比较排序质量、延迟与成本。通过消融分别验证需求特征、时效信息、可获得的个人贡献信号和证据融合的效果；贡献信息不全时不做确定性判断。

7.7 长期学习与总成本评估（RQ4–RQ5）

在同一基础模型和固定索引上，分别比较静态 Agent、仅反馈更新、仅自适应计算、两者简单叠加以及联合策略；固定反馈预算和更新批次，分别在未见新任务与旧任务保留集评价。模型、检索索引及反馈生成的变更需分开记录，避免把索引更新收益归因于学习策略。真实反馈与模拟反馈分别报告，并核算反馈采集、训练、评估和推理的总成本。

  1. 长期更新：按反馈批次评估新旧任务质量、遗忘率、跨领域迁移和策略稳定性。
  2. 质量约束：预先设定非劣界限，报告查询级配对置信区间与难度分组结果。
  3. 完整成本：统计查询推理、检索工具、反馈生成、训练、评估和部署的摊销费用，并以“单位成功检索总成本”作为主要成本指标。

补充统计与消融：同时报告 P50／P95／P99、超预算比例、查询级置信区间及质量非劣界限；比较反馈学习、自适应计算、直接叠加与联合优化。需求分类报告标注一致性、覆盖率与对检索路径的实际贡献。

8. 研究实施计划（Implementation Plan）

8.1 分阶段研究与独立交付

调整后的实施优先级：P0 冻结公开及企业评测协议与标注；P1 建立开源静态强基线并形成完整计时；P2 集中研究专家证据树、轻量 Decision Model、Embedding 微调和可选蒸馏，完成公开数据及企业数据的对照与消融；P3 集成初始框架，在相同预算下验证端到端质量与成本；P4 再单独验证在线／离线反馈改进。数据或反馈不足时保持相应结果未验证，不阻塞对初始搜索框架的研发和论文初稿。

P0 的版本化评测供全部阶段复用；P1 提供静态强基线，P2 比较可独立替换的检索与决策模块，P3 验证初始框架，P4 再研究反馈迭代。真实反馈不足不影响初始框架研究，但不能据此宣称持续学习收益。

10.2 与相关研究的区别

专家及来源的联合评价已有先例。TREC 2006 已在专家排序之外考察是否提交了真实的支持文档。本文的指标贡献需要进一步验证逐条硬约束的覆盖、原文与个人归属，以及在明确质量约束下的端到端成本。应同时报告独立的专家排序与证据支持指标。TREC 2006 任务综述

证据互补的强对照。首段固定时，投影版本等价于以查询与候选的相似度为相关项、以候选和首段的相似度为冗余项的 MMR 特例；冗余权重由首段和查询的相似度确定。GoldEn Retriever 已根据现有上下文生成后续查询以定位缺失实体。后续比较应保留固定余弦、验证集选权重的 MMR，以及同工具和预算的上下文查询改写。方法差异要落实到专家归属、硬约束支持或冲突状态，以及取证动作能否改善最终名单。MMR（SIGIR 1998） · GoldEn Retriever（EMNLP 2019）

  • AgentCL 研究受控任务流中的经验复用和迁移；本研究需进一步处理专家身份、来源级证据与需求约束，并区分经验更新和专家库更新。仅有记忆检索或随机划分不足以构成差异。
  • Long-Horizon Search Agents 轨迹诊断 区分证据未召回与已召回但未利用，并指出搜索次数与质量不必同步；本研究应继承逐阶段诊断，再验证面向专家排序的证据状态及停止决策是否带来增益。
  • AutoSearch 探索自适应搜索深度；简单减少搜索步骤并非独有创新。应在相同候选、模型、预算和完整成本下比较，并评估专家与证据质量。
  • Search Agent Training 的受控研究 强调检索覆盖、奖励及训练协议的混杂；本研究须固定语料与索引，分开检验机制、训练与数据变化。以上近期工作按预印本引用，不在此声称已发表顶会。

10.3 投稿前的证据门槛

  1. 机制归因：在固定组件和预算下，证明约束级证据状态比固定预算、分差早停和通用自适应策略带来额外收益；附失败案例与各模块消融。无需预设必须训练大模型，但训练方法须计入成本。
  2. 独立数据与可信质量：父需求／企业／近重复分组隔离，固定封闭测试；独立双人专家与来源判断、仲裁、覆盖及一致性；对未标注和未知贡献保留未知，公开许可允许的代码、数据和协议。
  3. 持续性与跨场景：核心框架在不同公开数据与独立专家库复现；若主张反馈贡献，再以真实或经过独立验证的反馈、固定更新批次和旧任务面板评价新任务迁移与遗忘，明确模拟与真实结果的区别。
  4. 质量—总成本：预先确定主要质量指标与非劣界限，报告成组配对不确定性、P50/P95/P99、失败、反馈／训练／索引摊销与 Pareto 曲线；不可把组件提速当作端到端收益。

10.4 论文定位与实际判断

若初始高效搜索框架在独立评测中取得可归因的质量—成本收益，并以充分的强基线和消融验证，SIGIR / The Web Conference 是优先考虑的主论文方向；若方法收益不足但数据、标注和复现协议达到独立价值，可考虑资源或评测方向，但须按目标会议当年征稿要求判断。KDD 更适合有规模化反馈与应用验证的成果；只有在方法超越本场景并体现通用持续学习贡献时，才考虑 NeurIPS。这些是研究适配判断，不是录用预测，也不要求必须使用强化学习。

当前最关键的研究决策：先建立可信的企业专家与证据评价，再验证初始框架能否在公开与企业场景中优于同预算强基线；反馈是否改善跨任务决策作为独立次要问题；若任一不成立，应保留结果并调整贡献，不以图示或组件速度替代主结果。
