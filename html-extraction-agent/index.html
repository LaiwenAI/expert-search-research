面向异构高校网页的结构感知数据提取 Agent

Structure-Aware HTML Extraction Agent for Heterogeneous Academic Websites
学源滔滔 · 技术研究方案 v2.0 · 2026-11-18

1. 研究背景（Background）

学源滔滔需要从高校及科研机构的教师主页、院系名录、成果列表和项目页面中提取结构化信息，并持续更新统一专家画像。网页来源高度异构：同一字段可能分别出现在表格、定义列表、自由文本、嵌套卡片和 JavaScript 渲染区域；同一页面还可能同时包含多位教师、数十篇成果和不相关的站点导航。

传统 XPath / CSS 规则提取速度快、成本低，但依赖模板；直接让大模型读取完整 HTML 则会引入冗余 token、记录间串扰、证据定位困难和高运行成本。简单的“去标签→按长度分块→LLM 抽取”同样不可靠，因为清洗与切块可能破坏姓名—职称、论文—作者、项目—时间等实体关系。

核心思路：先将 HTML 还原为可追溯的结构单元，优先复用确定性规则；仅对未知或异常结构调用 LLM，随后将经验证的提取方式归纳为可复用规则。输出不仅是 JSONL，还必须包含字段级来源证据、抽取状态和可重放的版本信息。

系统面临的主要技术挑战：

  1. 网页结构异构（Structural Heterogeneity）：院系、教师主页与成果列表的 DOM 模式不同，跨站点模板无法直接通用。
  2. 结构压缩与信息保真（Structure-Preserving Compression）：削减导航、样式和重复代码时，必须保留语义、链接、标签层级与父子关系。
  3. 多实体与长列表边界（Entity Boundary）：一个页面可能包含多个教师或多篇成果，分块不得截断单条记录，亦不能跨记录合并属性。
  4. 字段对齐与来源归属（Field Attribution）：相同字段可能有多个候选值，需要区分个人邮箱、办公室电话、学院公共邮箱等。
  5. 模板漂移与长期维护（Template Drift）：网页改版、标签重命名和异步加载会使已部署的 XPath 静默失效。
  6. 质量—延迟—成本约束（Quality–Latency–Cost）：高准确率不应建立在每个页面都进行多轮大模型推理的前提上。

4. 核心研究问题（Research Questions）

  1. RQ1 · 如何识别复杂 DOM 中的目标内容与实体边界？在名录、长成果列表、混排主页上提高实体分割准确率，避免跨人、跨成果字段串扰。
  2. RQ2 · 如何压缩 HTML 而不损失字段及其关系？在目标字段覆盖率不降低的条件下，减少 LLM 输入 token，并保留可验证的 DOM 路径。
  3. RQ3 · 如何协同 XPath 与 LLM？通过健康度检测、结构类型和预算约束，将确定性规则用于稳定模板，将语义推理集中在困难区域。
  4. RQ4 · 如何将成功的语义提取转化为可复用规则？从多样本学习稳定选择器，经历回归测试后发布，并及时发现模板漂移。
  5. RQ5 · 如何评价质量、时延和成本的联合收益？统一离线页面集、网络与模型条件，评估字段准确性、实体边界、证据归属和端到端成本。

研究依赖关系：RQ1 为 RQ2 提供完整语义单元；RQ1–RQ2 形成 RQ3 的低成本输入；RQ3 的已验证结果为 RQ4 提供候选训练样本；RQ5 贯穿全部模块，避免局部压缩收益掩盖总体质量下降。

5. 关键方法与技术路线（Methodology）

5.1 DOM 分析：先理解结构，再决定删除什么

DOM Analyzer 首先识别四类节点：全局模板（导航、页脚、广告）、内容容器（正文、名录主体）、实体单元（教师卡片、成果条目）、字段证据（标题、时间、链接、键值对）。结合标签语义、文本密度、链接密度、节点深度、重复兄弟子树和字段词典产生候选区域。

不建议统一删除 table、ul、a 或 img：教师联系方式经常存放于表格，科研成果通常是列表，主页和 DOI 藏于链接地址，头像可用于名录数据核对。script 通常可移除，但包含目标 JSON-LD 或页面数据对象时须先解析后再删除。

信号识别逻辑用途
重复子树兄弟节点标签路径、属性模式、文本分布相似识别多教师卡片与成果列表

5.2 保结构 HTML 简化（Structure-Preserving Simplification）

采用两级压缩：第一层移除脚本、样式和高置信模板噪声；第二层将冗余标签与属性归约为具有节点 ID 的紧凑表示。应保留文本、字段标签、层级、表格单元格映射、相对/绝对 URL、必要的图片替代文本和实体分组边界。

图 2. 示例：保留字段关系与可追溯节点编号
<div class="teacher-box">
  <h2>张某某</h2>
  <table>
    <tr><th>职称</th><td>教授</td></tr>
    <tr><th>邮箱</th><td>zhang@example.edu.cn</td></tr>
  </table>
</div>
↓ 结构归约（不丢失字段标签）
[entity id=e17 type=person xpath=//div[...]]
  [n21 heading] 张某某
  [n24 key=职称] 教授
  [n29 key=邮箱] zhang@example.edu.cn
  [source] e17/n24 → original XPath + text offsets
示意数据，非真实教师信息。LLM 消费简化表示；证据解析器仍以原始 HTML 快照核验。

定义压缩率 CR = 1 − tokens(simplified) / tokens(raw)；但 CR 只能作为效率指标，不能单独代表简化效果。必须同时测量字段覆盖率、证据可定位率与实体边界保持率。对于未知字段，先保存保守压缩的回退版本，避免激进删除导致不可恢复的漏抽。

5.3 结构感知分块：实体完整优先于固定 token

分块顺序建议为：页面类型 → 主内容区域 → 重复实体边界 → 栏目边界 → token 预算。对教师名录以卡片或表格行为最小单元；对成果列表以每条论文、专利为最小单元；对教师主页按“个人信息 / 研究方向 / 论文 / 项目”等语义小节分块，并在每块携带所属教师的稳定实体 ID。

图 3. 分块粒度与跨块上下文
页面级上下文

URL、院系、页面标题、页面语言、主实体 ID

实体块

教师卡片 A / 教师卡片 B / 论文条目 i … 每条保持完整

字段证据

姓名 n21、职称 n24、邮箱 n29，输出前逐项反查

超长单实体可按语义小节继续拆分，但须携带实体上下文与连续序号；合并时以实体 ID 与字段类型校验。

采用两种策略：pack（将多个完整小实体装入同一模型请求，仍保持边界标记）和 split（对超长单实体按栏目拆分）。不得将列表从任意 token 位置硬截断。对跨块值（如论文条目后附统一年份标题），需显式继承栏目上下文，而不是让模型自由猜测。

5.4 确定性优先：XPath / CSS / JSON-LD

命中既有模板且规则健康时，优先使用 XPath/CSS；结构化数据（例如 JSON-LD）可以成为另一条确定性提取路径。规则应包含域名或模板作用域、字段名、选择器、期望数据类型、命中基数、正负样本与回归集。避免仅以“XPath 非空”判定成功：新模板可能让 XPath 命中错误的学院公共邮箱。

from scrapy import Selector

sel = Selector(text=html)
name = sel.xpath(
    "//main//h1[1]/normalize-space()"
).get()  # 实际使用时应采用下面更可靠的形式

name = sel.xpath("normalize-space((//main//h1)[1])").get()
emails = sel.xpath(
    "//a[starts-with(@href, 'mailto:')]/@href"
).getall()

# 规则执行后：检查范围、基数、格式、与证据节点的对应关系

以上为接口示意；XPath 表达式以样本模板调整。Scrapy Selector 支持 XPath / CSS 选择器，规则需用本地快照测试后部署。

5.5 LLM 提取：严格输出契约、字段证据必填

LLM 只接收必要块、页面上下文与 Schema 子集，要求每个非空字段都返回来源节点 ID（或可验证的原文 span），并明确未知字段。Prompt 不要求模型根据常识补充机构、职称、邮箱或成果信息；不能定位来源时，字段应置空并标注待复核。

{
  "entity_id": "e17",
  "fields": {
    "name": {"value": "张某某", "node_ids": ["n21"]},
    "title": {"value": "教授", "node_ids": ["n24"]},
    "email": {"value": "zhang@example.edu.cn", "node_ids": ["n29"]}
  },
  "unresolved": []
}

LLM 返回后需要独立于 LLM的证据核验器逐字段检查：节点是否真实存在、值是否被原文支持、归属实体是否一致、日期与 URL 是否可以规范化。模型自报置信度不等同于已验证正确率，也不能替代证据校验。

5.6 Agent 路由与停止条件（Routing & Stopping）

表 5　分层决策策略（初始版本）
状态动作停止 / 升级条件
规则命中、证据通过、关键字段完整使用 XPath / JSON-LD 结果直接输出；抽样质量审计
规则未命中或页面类型未知DOM 简化后调用 LLM输出经验证字段；记录未知模式

动态加载导致内容缺失按权限与预算重试渲染版 DOM渲染失败则部分输出或错误状态
质量仍不达标且预算耗尽保留可信字段，入待审队列不得生成未经支持的完整记录

可以从可解释规则路由起步，后续再用真实运行数据训练成本敏感的决策器；暂时不建议引入复杂强化学习。候选动作的经验价值必须基于真实数据验证，不能将人为设定的“置信度阈值”当成已证实最优策略。

min E[cost + λ · latency]　s.t.　quality ≥ q₀,　evidence_valid = true

这里的质量约束指在固定测试集上达到预设门槛；λ 与 q₀ 是实验协议指定的权重/门槛，不代表已验证取值。

5.7 XPath 规则归纳、发布与自愈

LLM 成功提取一次，不意味着生成的 XPath 可以立即上线。推荐流程：收集同模板的已验证节点 → 生成多种选择器候选 → 用正例与同页负例测试 → 评估命中稳定性、误命中和唯一性 → 独立回归集通过后发布。规则作用域优先绑定“站点 + 模板指纹”，而非盲目绑定整个域名。

图 4. 规则学习与模板漂移检测
已验证样本XPath + 字段证据
候选规则泛化相对路径
测试筛选正负样本 / 稳定性
灰度启用版本 / 回滚
漂移监测命中率 / 错误率
规则异常时自动降级至 LLM 或人工审核，并保留旧版规则与失败快照用于诊断。

防止错误自我强化：LLM 抽取结果不能在未经验证的情况下直接成为 XPath 训练金标；模型与规则互相认可不构成独立证据。候选规则必须通过与生成样本相互独立的测试集，线上保留人工抽检。

5.8 多页融合与增量更新

网页级 JSONL 是抽取层的原子产物，跨页专家合并应放到下游实体对齐层执行。保留 source_url、snapshot_hash、observed_at 和证据时间，不因为不同页面出现同名就自动合并。对增量采集，先比对内容指纹与结构指纹，再判定是否重新抽取；注意正文不变而页脚变动时不必触发全量 LLM。

6. 输出数据与证据模型（Data Contract）

6.1 输出 JSONL

建议将业务字段和可溯源元数据分离。业务 JSONL 每行代表一个实体，保持稳定的字段类型；证据记录可单独存储为伴随 JSONL，以免将大量 XPath/文本片段反复复制到业务数据。以下为示意（不含真实人物信息）：

{"record_id":"r001","entity_type":"person","name":"张某某","title":"教授","email":"zhang@example.edu.cn","research_interests":["机器学习"],"source_url":"https://example.edu.cn/teacher/17","snapshot_hash":"sha256:...","extraction_status":"verified"}
{"record_id":"r002","entity_type":"person","name":"李某某","title":null,"email":null,"research_interests":[],"source_url":"https://example.edu.cn/teachers","snapshot_hash":"sha256:...","extraction_status":"partial"}

6.2 字段级证据（Field-Level Provenance）

{"record_id":"r001","field":"title","value":"教授","source_url":"https://example.edu.cn/teacher/17","snapshot_hash":"sha256:...","node_id":"n24","xpath":"//main//table[1]/tr[1]/td[1]","raw_text":"教授","method":"xpath","verification":"supported","rule_version":"siteA-v3"}

节点 ID 是一次快照内的稳定引用，不应被当作跨网页版本的永久键。XPath 仅用于在同一快照中回溯；新版网页结构改变后，可能需要基于内容锚点与模板重定位。统一 Schema 可映射至学源滔滔的专家画像字段，不强制每个页面都填满完整画像。

7.3 关键处理流程（伪代码）

def extract_page(snapshot, schema, policy):
    dom = parse(snapshot.html)
    page_type, regions = analyze_dom(dom)
    units = detect_entity_boundaries(regions, page_type)
    records = []

    for unit in units:
        rule = registry.match(snapshot.url, unit.fingerprint)
        candidate = extract_by_rule(unit, rule) if rule else None

        if not evidence_pass(candidate, unit, schema):
            compact, node_map = simplify(unit, schema)
            chunks = chunk_by_entity(compact, policy.token_budget)
            candidate = llm_extract(chunks, schema, node_map)

        verified = validate_against_snapshot(candidate, dom, schema)
        records.append(verified)

    write_jsonl(records)
    save_evidence_and_diagnostics(records, snapshot)
    queue_rule_learning(verified_examples(records))
    return records

这是模块级伪代码，并非可直接运行的生产实现；异常捕获、重试、异步调度与模型调用细节在工程开发阶段补齐。

7.4 运行安全与数据治理

遵守适用法律、站点访问政策与 robots 约束；按域名限制速率并设置重试上限，不绕过登录权限或反爬安全机制。网页文本应视为不可信输入：任何嵌入的“忽略指令”均不得改变 Agent 的提取策略、工具权限或输出 Schema。限制外链访问、模型传输字段、日志中个人信息展示，并制定快照保留和删除策略。

10. 风险、边界与工程判断（Risks & Design Decisions）

  1. 不要把正文提取当作通用结构提取。Trafilatura 等主内容提取工具适合作为基线，但对教师名录、表格和多实体关系通常需要额外的结构化分割逻辑。
  2. 不要追求最高压缩率。过度压缩可能删除邮箱所属人、成果年份标题与原始链接，导致“低 token、高错误”。
  3. 不要让 LLM 自己验证自己。字段支持必须由原始 DOM/快照回查；规则训练需要独立测试集。
  4. 不要将选择器匹配成功等同于提取正确。模板漂移经常产生“非空但错位”的结果，必要时保留人工抽样审计。
  5. 不要把网页提取层与跨站实体合并混成一个 Agent。抽取结果可带候选关联，但最终实体对齐应由独立模块执行，保留冲突证据。
  6. 不要默认动态渲染。浏览器资源昂贵，先尝试静态 HTML；必要时依据页面特征触发渲染。

总体判断：该项目的真正技术价值不是“Scrapy + LLM”本身，而是可验证的结构保持、实体边界一致性、选择器自适应复用及其在质量门槛下的成本优势。前两者决定准确性，后两者决定长期规模化价值。
