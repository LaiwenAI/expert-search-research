面向高校专家数据的结构感知网页提取 Agent

Structure-Aware HTML Extraction Agent for Academic Expert Data
学源滔滔 · 技术方案 v1.0 · 2026-11-18
核心思路

利用 XPath 完成低成本的确定性定位，利用 LLM 解决异构网页的语义理解，并通过规则学习减少后续模型调用。对复杂 HTML 先分析、去噪、保留证据路径，再按语义边界分块提取，最终生成可追溯、可验证的 JSONL。

1. 背景与目标（Background & Objectives）

高校教师主页、学院师资目录、科研成果页面存在模板多样、表格嵌套、字段命名不统一、中英文混排和动态渲染等问题。单纯 XPath 规则维护成本高，直接向 LLM 输入整页 HTML 又存在 token 浪费、上下文截断、跨记录混淆和证据缺失。

目标是建立可复用的数据提取引擎，输入网页 URL 或 HTML 快照及目标 Schema，输出多条 JSONL 记录和字段级来源；支持单人主页、多人列表、论文/项目列表等页面类型。

2. 设计原则（Design Principles）

  1. 结构先于语义：先分析 DOM、表格、列表、标题和链接，再调用 LLM。
  2. 确定性优先：已有可信 XPath 规则直接执行；仅在未知模板、规则失效、语义歧义时升级模型。
  3. 证据不丢失：简化 HTML 时保留节点 ID、XPath、href、表格行列关系、标题层级和原文。
  4. 记录边界优先：先切分“教师/论文/项目”等记录，再按 token 预算切块，禁止随意跨记录切割。
  5. 不凭空补全：缺失字段输出 null，推断字段单独标识，不得把模型猜测写成网页事实。
  6. 持续学习：通过验证的结果反向生成并测试 XPath 规则，按站点/模板版本缓存。

4. 核心技术路线（Methodology）

4.1 页面解析与结构分析

使用 Scrapy/parsel 解析 HTML，记录 DOM 树、节点 XPath、文本长度、链接密度、标签类型、class/id 特征、同级结构相似度和表格布局。将页面初步识别为个人主页、列表页、详情页、混合页或未知类型；检测重复卡片、表格行、列表项等候选记录边界。页面类型分类允许不确定并回退到通用结构切分。

4.2 HTML 简化：压缩但不破坏关系

删除 script、style、注释和明显导航/页脚等非内容区域，但保留正文中有意义的 a[href]、标题、img[alt]、表格单元格及合并单元格信息。不能无条件丢弃隐藏节点或全部链接；有些教师信息由链接文字、标签或 JS 数据承载。

<section data-node="n42" data-xpath="//div[@class='teacher']">
  <h2 data-node="n43">张三</h2>
  <p data-node="n44">研究方向：知识图谱、信息检索</p>
  <a data-node="n45" href="/faculty/zhang">个人主页</a>
</section>

可进一步生成 结构化中间表示（IR）：{node_id, xpath, role, text, attrs, parent_id, record_id}，供分块、模型提示和证据回查共同使用。保留原始 HTML 快照，简化后的内容不是唯一事实来源。

4.3 结构感知分块

优先以重复卡片、表格行、人物块和标题章节为切分单位；大块内部按语义段落继续拆分。每块附带页面标题、所属章节、记录 ID、原始节点路径和少量相邻上下文。对超长单条记录允许分块提取后合并，但禁止将相邻教师的属性混为一人。

4.4 双通道提取

规则通道：站点/模板指纹命中且回归测试通过时执行 XPath。LLM 通道：仅处理未覆盖字段、未知结构、异常记录或冲突字段。要求模型返回严格 JSON，字段值尽可能附带 node_id 和原文引用；禁止生成未经校验的 XPath 作为直接生产规则。

4.5 验证与合并

首先执行 JSON Schema/Pydantic 类型检查；随后使用节点 ID 回查原文，检查值是否得到支持，链接是否可解析、人员记录是否串行、重复项是否应合并。字段冲突保留候选证据和冲突状态，不能简单由 LLM 选择看似合理的一项。不同来源的教师身份合并属于独立的实体对齐步骤。

4.6 规则归纳与自愈

对经过验证的多个同模板样本，归纳相对 XPath（如卡片根节点下的姓名/研究方向字段），在留出页面上检查覆盖率和精确率。只有通过阈值的规则才进入规则库；模板指纹改变或字段异常率升高时停用规则并触发重新分析。

5. Agent 决策机制（Agent Policy）

状态动作触发条件
FETCH获取静态 HTML / 必要时渲染原始内容缺失或关键区域由 JS 加载
ANALYZEDOM 分类与记录边界识别首次页面或结构指纹变化
RULE执行缓存 XPath规则存在且质量监控正常
LLM只提取缺失或冲突部分规则覆盖不足或字段歧义
VERIFY校验并回查证据所有候选记录
REPAIR重新分块、重试或人工复核证据不符、记录串扰、校验失败
STOP输出 JSONL 与质量报告达到质量门槛或预算耗尽

控制变量包括最大 LLM 调用次数、最大 token、重试次数、字段重要度、页面质量和时间预算。预算耗尽时允许输出部分已验证记录，并明确标记未完成字段。

6. JSONL 与证据设计（Output Contract）

建议把业务字段与提取元数据分开：业务字段映射到学源滔滔统一教师画像 Schema，元数据负责来源与审计。下例仅为示意，不代表平台完整字段定义。

{"record_type":"expert","data":{"name":"张三","research_interests":["信息检索","知识图谱"],"homepage":"https://example.edu/faculty/zhang"},"evidence":{"name":{"node_id":"n43","xpath":"//section[1]/h2","quote":"张三"},"research_interests":{"node_id":"n44","quote":"研究方向：知识图谱、信息检索"}},"meta":{"source_url":"https://example.edu/faculty","snapshot_id":"sha256:...","extractor":"llm","schema_version":"1.0","status":"verified"}}

每行是一条 JSON 对象；多教师列表生成多行。对多值字段可将 evidence 扩展为证据数组。正式生产环境还应记录 retrieved_at、模型版本、规则版本、字段级状态、原始值与规范化值。

8. 评测与实验（Evaluation）

固定 HTML 快照、目标 Schema、模型版本和评测集；按高校/站点/模板分组划分训练、开发和测试集，避免同模板泄漏。分别统计字段级精确率、召回率、F1、记录边界准确率、JSON 有效率、证据定位准确率、跨人字段污染率、端到端延迟和每千条有效记录成本。

对照方法检验问题
B1纯 XPath 人工规则规则维护成本与覆盖率
B2整页 HTML → LLM结构分析和分块是否必要
B3纯文本/Markdown → LLM保留 DOM 关系是否改善质量
B4结构分块 → LLM分块收益
Ours结构分块 + XPath + 按需 LLM + 规则学习质量、速度、成本联合收益

消融实验依次移除：结构感知分块、节点证据、XPath 快速路径、规则归纳和字段级重试。目标不是先验宣称优于基线，而是通过固定数据集验证增益。

10. 风险与边界（Risks）

  1. 动态网页、iframe、PDF 附件和图片中的信息需独立处理；本方案的 HTML 提取不等于覆盖所有媒介。
  2. 页面中可能存在恶意指令；网页内容一律作为不可信数据，不能让网页文字修改 Agent 的工具权限或系统指令。
  3. 遵守网站访问规则、合理限速、隐私和个人信息处理要求；不以绕过登录、验证码或访问控制为默认能力。
  4. LLM 可能漏字段或跨记录串扰，必须使用字段级原文证据和独立验证，不能仅依赖模型自报置信度。
  5. XPath 对页面改版敏感；规则上线前需要留出样本验证与漂移监测。
